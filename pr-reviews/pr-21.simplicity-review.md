## Summary

This PR adds individual-year line plotting to seasonal plots when ≤5 years are present. The implementation is **straightforward but suffers from significant code duplication**. The same ~40-line conditional block (individual year vs envelope rendering) appears **four times** in `seasonal.py` across single-run, comparison, and faceted plotting paths. The helper function `compute_individual_year_seasonal_cycles()` is well-factored, but the rendering logic was not extracted, leading to maintenance burden and increased diff size.

Diff size: **+422** lines added / **-24** removed across 8 files.
Reduction estimate (best-case if all suggestions applied): **~150 LOC** by extracting the duplicated rendering logic into a single helper function.

## Findings

### Finding 1: Duplicated rendering logic across plotting paths
**Severity:** suggested
**Category:** duplication
**Location:** `elm_diagnostics/plots/seasonal.py:254-340, 369-404, 526-618, 644-683`

**Issue:** The conditional logic that decides between individual-year lines (thin + thick mean) vs envelope rendering appears four times with minimal variation:
1. Lines 254-340: `_plot_seasonal_single()` for Comparison (no level_dim)
2. Lines 369-404: `_plot_seasonal_single()` for Run (no level_dim)
3. Lines 526-618: `_plot_seasonal_faceted()` for Comparison (no level_dim)
4. Lines 644-683: `_plot_seasonal_faceted()` for single Run (no level_dim)

Each block is ~35-45 lines and follows the same pattern:
- Compute years/cycles via `compute_individual_year_seasonal_cycles()`
- Check threshold
- If below: loop over years, plot thin lines, plot thick mean
- Else: fill_between envelope, plot mean line

The only differences are:
- Variable names (`da_base`/`da_exp` vs `da`)
- Colors (gray/tab:blue for comparison, just tab:blue for single run)
- Legend labels (include run names for comparison, years only for single run)

**Recommendation:** Extract a helper function that encapsulates the conditional rendering:

```python
def _plot_seasonal_with_years_or_envelope(
    ax,
    months,
    da,
    mean,
    lo,
    hi,
    config,
    *,
    color="tab:blue",
    label_prefix="",
    include_climos=True,
):
    """Plot seasonal cycle with individual years (≤threshold) or envelope (>threshold)."""
    years, year_cycles = compute_individual_year_seasonal_cycles(
        da,
        config.plots.climatology.climo_start_year,
        config.plots.climatology.climo_end_year,
    )
    n_years = len(years)
    
    if n_years <= config.plots.climatology.show_individual_years_threshold:
        # Plot individual year lines
        for year, year_mean in zip(years, year_cycles):
            ax.plot(
                months,
                year_mean.values,
                color=color,
                alpha=0.3,
                linewidth=1,
                label=f"{label_prefix}{year}" if label_prefix else str(year),
            )
        # Plot mean as thick line
        ax.plot(
            months,
            mean.values,
            color=color,
            linewidth=3,
            label=f"{label_prefix}mean ({n_years} years)" if label_prefix else f"Mean ({n_years} years)",
        )
    else:
        # Envelope + mean
        if include_climos:
            ax.fill_between(months, lo.values, hi.values, alpha=0.2, color=color)
        ax.plot(
            months,
            mean.values,
            color=color,
            linewidth=2,
            label=label_prefix.strip() if label_prefix else None,
        )
```

Then call it once for single-run, twice for comparison (base + exp). This would eliminate ~120 lines of duplication.

### Finding 2: Comparison path computes individual years even when not needed
**Severity:** nit
**Category:** yagni
**Location:** `elm_diagnostics/plots/seasonal.py:254-266, 526-538`

**Issue:** In the comparison plotting path, `compute_individual_year_seasonal_cycles()` is called for both base and experiment **unconditionally**, even when the threshold check might short-circuit to envelope rendering. If one run has 6 years and the other has 100 years, the code still computes individual year cycles for the 100-year run even though the threshold condition uses `or` (either run ≤5 triggers individual-year mode).

**Recommendation:** Move the computation inside the conditional if the short-circuit is valuable, or document that the computation cost is negligible (likely true for ≤12 months/year).

**Patch:** If optimizing:
```python
# Compute years for threshold check only
years_b = sorted({_get_year(t) for t in da_base.time.values})
years_e = sorted({_get_year(t) for t in da_exp.time.values})
n_years_b = len(years_b)
n_years_e = len(years_e)

if n_years_b <= threshold or n_years_e <= threshold:
    # Now compute full cycles
    _, year_cycles_b = compute_individual_year_seasonal_cycles(...)
    _, year_cycles_e = compute_individual_year_seasonal_cycles(...)
    # ... render
```

However, this may not be worth the added complexity; mark as **nit** unless profiling shows `groupby("time.month").mean()` is expensive.

### Finding 3: Faceted comparison path drops year labels in legend
**Severity:** nit
**Category:** diff-hygiene
**Location:** `elm_diagnostics/plots/seasonal.py:548-555, 567-574`

**Issue:** In the faceted comparison path (lines 526-618), individual year lines are plotted **without** year labels:
```python
for year_mean in year_cycles_b:  # note: no `year` variable
    ax_i.plot(months, year_mean.values, color="gray", alpha=0.3, linewidth=1)
```

Compare to the non-faceted path (lines 274-282), which includes `label=f"{source.base.name} {year}"`. This inconsistency suggests the faceted path accidentally lost the year labels during copy-paste, or intentionally omitted them to reduce legend clutter.

**Recommendation:** Either:
- Add the year labels for consistency (but faceted legends may become crowded)
- Document why they're omitted (e.g., "faceted plots omit individual year labels to reduce legend size")
- Remove the `year` variable from the zip since it's unused: `for year_mean in year_cycles_b:`

The current code zips `years_b, year_cycles_b` but never uses `year`, which is misleading.

**Patch:**
```python
# Option 1: Remove unused variable
for year_mean in year_cycles_b:
    ax_i.plot(...)

# Option 2: Add labels (if legend space allows)
for year, year_mean in zip(years_b, year_cycles_b):
    ax_i.plot(..., label=f"{year}")
```

## Overall Assessment

The feature implementation is **functionally complete and correct**, with good test coverage (3 new tests exercising the key paths). The `compute_individual_year_seasonal_cycles()` helper is well-factored and reusable. The configuration addition is appropriately minimal (one field, sensible default).

However, the **significant code duplication in the rendering logic** (Finding 1) is the main simplicity concern. The duplicated block appears 4 times and accounts for ~140 lines of the +422 added. Extracting a helper function would reduce the diff by ~35%, improve maintainability, and make future changes (e.g., adjusting line styles, adding new threshold logic) much easier.

The secondary findings (2-8) are minor: premature computation (Finding 2) is likely negligible, test duplication (Finding 4) is standard pytest verbosity, and scope creep (Findings 5-6) / formatting churn (Findings 7-8) add noise but don't affect runtime behavior.

**Recommendation:** Address Finding 1 (extract rendering helper) before merging. This will reduce the maintenance surface area and make the feature more robust to future changes. Findings 2-8 are optional cleanup.

**Blocking status:** Per the spec's `post_completion_review.blocking` field (not provided in the pseudo-spec), this review defaults to **non-blocking**. However, the duplication in Finding 1 is substantial enough to warrant a "suggested" severity — it should be addressed to avoid technical debt.
