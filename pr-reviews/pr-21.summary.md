## Overview

This PR adds support for displaying individual year lines in seasonal plots when datasets contain ≤5 years, improving visibility of year-to-year variability in short time series. The implementation is functionally correct and well-tested, but has **2 blocking issues** that must be addressed before merge, plus several optimization and simplification opportunities.

---

## Critical Issues (BLOCKING)

### 1. Legend Pollution in Comparison Plots
**Severity:** BLOCKING  
**Source:** Code Review - Finding 1  
**Location:** `elm_diagnostics/plots/seasonal.py:274-281, 294-301`

Individual year lines in comparison plots include labels (e.g., "base 2000", "base 2001"), creating cluttered legends with 10+ entries for a 5-year comparison. The faceted path correctly omits these labels.

**Fix:** Remove `label` parameter from individual year line plots in the comparison path.

---

### 2. Threshold Boundary Ambiguity
**Severity:** BLOCKING  
**Source:** Code Review - Finding 2  
**Location:** `elm_diagnostics/plots/seasonal.py:270, 254, 424; elm_diagnostics/config/schema.py:50`

The config parameter `show_individual_years_threshold: int = 5` uses `<=` comparison, meaning exactly 5 years shows individual lines. While this may be intentional, there's no docstring clarifying the semantics and no test for the boundary case (exactly 5 years).

**Fix:** 
1. Add docstring to config field explaining threshold behavior
2. Add test case for exactly 5 years

## Major Concerns (Recommended Before Merge)

### 3. Code Duplication in Plotting Logic
**Severity:** SUGGESTED  
**Source:** Simplicity Review - Finding 1  
**Location:** `elm_diagnostics/plots/seasonal.py`

The conditional rendering block for individual year lines is duplicated **4 times** (~40 lines each) across single-run, comparison, faceted-single, and faceted-comparison paths. This adds ~140 redundant lines to the diff.

**Impact:** Maintenance burden — future changes to rendering logic (e.g., different alpha values) require 4 parallel edits.

**Recommendation:** Extract a helper function `_plot_individual_year_lines()` to eliminate duplication.

---

### 4. Redundant Computation for Threshold Check
**Severity:** MEDIUM  
**Source:** Performance Review - Finding 1  
**Location:** `elm_diagnostics/plots/seasonal.py:255-266, 370-375`

For datasets >5 years, the code calls `compute_individual_year_seasonal_cycles()` (expensive year-by-year groupby operations) only to immediately discard results when the threshold check fails. A 10-year dataset performs 10 unnecessary `groupby().mean().compute()` calls.

**Impact:** 100% wasted computation for datasets above threshold.

**Recommendation:** Add fast-path `count_years_in_window()` function to check threshold before computing seasonal cycles.

## Performance Optimizations (Nice to Have)

### 5. Inefficient Year Masking
**Severity:** MEDIUM  
**Source:** Performance Review - Finding 2  
**Location:** `elm_diagnostics/plots/climatology.py:119-120`

Year extraction via list comprehension runs 60×5=300 times for a 5-year monthly dataset.

**Fix:** Extract years once before the loop, reducing `_get_year()` calls by 80%.  
**Estimated speedup:** 10-20% of `compute_individual_year_seasonal_cycles()` runtime.

---

### 6. Premature `.compute()` Defeats Lazy Evaluation
**Severity:** MEDIUM  
**Source:** Performance Review - Finding 3  
**Location:** `elm_diagnostics/plots/climatology.py:126`

Eager `.compute()` on each year's seasonal cycle prevents dask from optimizing task graphs and can cause redundant I/O for chunked datasets.

**Fix:** Build list of lazy arrays and compute all at once via `xr.concat().compute()`.  
**Estimated speedup:** 20-40% for dask-backed datasets.

---

### 7. Repeated Computation in Faceted Plots
**Severity:** MEDIUM  
**Source:** Performance Review - Finding 4  
**Location:** `elm_diagnostics/plots/seasonal.py:301-314, 417-428`

For sub-gridcell faceted plots, `compute_individual_year_seasonal_cycles()` runs independently for each column/PFT/landunit, repeating identical temporal processing.

**Impact:** For 10 columns × 5 years, this is 10× redundant work.  
**Recommendation:** Compute year cycles once across all facets, then slice by facet.
