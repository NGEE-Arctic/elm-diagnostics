# Code Review: PR 26 - Restructure HTML report to multi-page layout with navigation menu

Reviewed: 2026-08-24
Reviewer: code-reviewer

## Summary

PR 26 successfully converts the single-page HTML report to a multi-page layout with navigation. The implementation is generally sound with good template inheritance, proper file path handling, and comprehensive test coverage (30 tests passing). However, there are several **blocking** issues related to error handling, dead code, and potential runtime failures that must be addressed before merging.

## Findings

### Finding 1: Missing error handling in _copy_assets
**Severity:** blocking
**Location:** elm_diagnostics/report/build.py:1608-1613
**Issue:** `_copy_assets()` uses `shutil.copy2()` without error handling. If source assets are missing or target directory is not writable, the build will crash with an unhandled exception instead of providing a useful diagnostic message.
**Recommendation:** Add try-except block with informative error message:
**Patch:**
```python
def _copy_assets(self, assetsdir: Path) -> None:
    """Copy CSS and JS assets to output assets/ directory."""
    import shutil

    try:
        shutil.copy2(_ASSETS_DIR / "style.css", assetsdir / "style.css")
        shutil.copy2(_ASSETS_DIR / "lightbox.js", assetsdir / "lightbox.js")
    except FileNotFoundError as e:
        logger.error(f"Asset file not found: {e}")
        raise RuntimeError(
            f"Required asset file missing from {_ASSETS_DIR}. "
            "Report generation cannot continue."
        ) from e
    except (OSError, IOError) as e:
        logger.error(f"Failed to copy assets to {assetsdir}: {e}")
        raise RuntimeError(
            f"Cannot write to output directory {assetsdir}. "
            "Check permissions."
        ) from e
```

### Finding 3: Missing error handling for template loading
**Severity:** blocking
**Location:** elm_diagnostics/report/build.py:1669
**Issue:** `env.get_template("section.html.j2")` will raise `jinja2.TemplateNotFound` if the template is missing, but there's no error handling. This makes debugging difficult for users if templates are accidentally deleted or the package is improperly installed.
**Recommendation:** Add try-except with helpful error message:
**Patch:**
```python
try:

        "Package installation may be corrupted."
    ) from e
```

### Finding 4: Hardcoded "Run Information" check is fragile
**Severity:** suggested
**Location:** elm_diagnostics/report/build.py:1601, 1704
**Issue:** The code checks for `section.title == "Run Information"` in two places to determine the landing page. This is fragile - if the section title is changed elsewhere in the codebase (e.g., for internationalization or style), these checks will silently fail.
**Recommendation:** Use a more robust check such as index position or add an explicit `is_landing_page` boolean to `_Section`:
**Patch:**
```python
# In _assign_section_filenames:
for idx, section in enumerate(sections):
    if idx == 0:  # First section is always landing page
        section.filename = "index.html"
    else:
        slug = re.sub(r"[^a-z0-9]+", "-", section.title.lower()).strip("-")
        section.filename = f"{slug}.html"

# In _render_multi_page_html:
if section.filename == "index.html":  # Check filename, not title
    template_vars["summary"] = summary
```

### Finding 5: Potential file path issues with file:// URLs
**Severity:** suggested
**Location:** elm_diagnostics/report/templates/base.html.j2:7, 35
**Issue:** Asset and navigation links use relative paths (`href="assets/style.css"`, `href="{{ section.filename }}"`). While this should work for `file://` URLs, different browsers handle `file://` protocol differently. The tests don't verify actual browser rendering with `file://` URLs.
**Recommendation:** This is acceptable for the stated requirement "no web server required," but add a comment in the template explaining the assumption. Consider adding an integration test that opens the HTML in a headless browser to verify links work.
**Patch:**
```html
{# Asset paths are relative to support file:// URLs without a web server.
   All HTML files must be in the same directory as the assets/ subdirectory. #}
<link rel="stylesheet" href="assets/style.css">
```
